# Тест-кейсы (черновик) — Smart Restaurant
**Версия:** 0.1
**пересмотр одобрен:** 
**Автор:** QA/QC
**Статус:** предварительный подход к тестированию до начала реализации; требует согласования с командой

## 1. Формат тест-кейса

| Поле | Описание |
|------|----------|
| ID | TC-<Область>-<NNN>, например TC-BOK-001 |
| Область | Бронирование / Конструктор / Менеджер / Визуализация / Доступность / НФТ |
| Бизнес-правило | Ссылка на BP-XX из test-approach.md §11 |
| Тип | unit / integration / e2e |
| Precondition | Что должно быть готово перед запуском |
| Шаги | Нумерованные действия актора / системы |
| ОР | Ожидаемый результат |
| Приоритет | P0 (критично для MVP) / P1 / P2 |
| Статус | черновик |

## 2. Бизнес-правила (краткая выписка из §11)

BP-01 — нет овербукинга с буфером 15 мин.
BP-02 — буфер 15 мин учитывается при расчёте слотов.
BP-03 — публикация схемы 409 при конфликте с будущими бронями.
BP-04 — soft-lock стола на 5 мин при оформлении.
BP-05 — soft-lock конструктора через WebSocket.
BP-06 — отмена гостем до T_start − 1 час.
BP-07 — no-show через 20 мин; блокировка аккаунта при 3 no-show.
BP-08 — матрица доступа ролей (гость / конструктор / менеджер / админ).
BP-09 — доступность стола по флагам зоны и стола.

## 3. Тест-кейсы: Бронирование (BOK)

### TC-BOK-001 | Доступность стола на слот | BP-01, BP-02 | integration | P0
Precondition: в БД есть стол T-1 ( seats = 4, isReservable=true ), зона активна, на стол есть confirmed бронь 
Шаги:
1. Запросить доступность стола T-1 на интервал (пересекается с броней).
2. Запросить доступность стола T-1 на интервал (начало через 15 мин после конца + буфер).
ОР:
1. Статус «занят», бронь невозможна.
2. Статус «свободен», бронь возможна.

### TC-BOK-002 | Овербукинг при параллельных запросах | BP-01 | integration | P0
Precondition: стол T-1 свободен.
Шаги:
1. Одновременно отправить 2 запроса на создание confirmed брони для T-1 от разных пользователей.
ОР: ровно одна бронь создана (confirmed); второму возвращается отказ (409) с сообщением о недоступности.

### TC-BOK-003 | Soft-lock стола 5 мин | BP-04 | unit + e2e | P1
Precondition: гость выбрал стол и открыл модалку оформления.
Шаги:
1. Зафиксировать начало мягкой блокировки (таймер 300 с).
2. Попытаться забронировать тот же стол другим пользователем в течение 5 мин.
3. Подождать истечения 5 мин без действия.
ОР: в течение 5 мин стол заблокирован для других; после истечения — снова доступен.

### TC-BOK-004 | Отмена гостем до T_start − 1 час | BP-06 | integration | P1
Precondition: confirmed бронь начинается в n.
Шаги:
1. Гость инициирует отмену своей брони.
2. Повторить отмену  (за n мин до начала).
ОР: 1 — отмена успешна; 2 — отмена отклонена с объяснением.

### TC-BOK-005 | Гостевая бронь «под ключ» | BP-01, BP-04, BP-09 | e2e | P0
Шаги:
1. Гость выбирает дату, время, количество гостей.
2. Система отображает 2D-схему с цветовой подсветкой доступности.
3. Гость кликает на свободный подходящий стол.
4. Стол блокируется на 5 мин, гость вводит контакты и подтверждает.
ОР: создана запись Reservation со статусом confirmed, стол занят на интервал + 15 мин буфер, отправлено подтверждение.

## 4. Тест-кейсы: Конструктор (CON)

### TC-CON-001 | Публикация схемы с конфликтом future-броней | BP-03 | integration | P0
Precondition: на столе T-2 есть future confirmed бронь. Конструктор удаляет T-2 или уменьшает seats ниже числа гостей в брони.
Шаги:
1. Нажать «Опубликовать схему».
ОР: публикация заблокирована, HTTP 409, выведен список конфликтующих броней, старая ревизия остаётся активной.

### TC-CON-002 | Откат ревизии схемы | — | integration | P1
Шаги:
1. Опубликовать ревизию #2.
2. Откатиться к ревизии #1.
ОР: активной становится ревизия #1, гости и менеджер видят схему #1, история сохраняет обе ревизии.

### TC-CON-003 | Soft-lock конструктора | BP-05 | e2e | P1
Шаги:
1. Сессия A открывает конструктор для редактирования схемы этажа.
2. Сессия B открывает ту же схему для редактирования.
ОР: сессия B получает режим только чтения и уведомление, что схему редактирует другой пользователь.

## 5. Тест-кейсы: Менеджер (MGR)

### TC-MGR-001 | no-show через 20 мин | BP-07 | e2e | P1
Precondition: confirmed бронь начинается , гость не явился.
Шаги:
1. Менеджер фиксирует no-show.
2. Повторить для того же гостя ещё дважды в отдельных визитах.
3. Попросить админа проверить аккаунт гостя.
ОР: 1 — статус брони no_show, стол освобождается; 3 — админ блокирует аккаунт гостя (isBlocked=true).

### TC-MGR-002 | Ручное создание брони по телефону | BP-01, BP-02 | integration | P1
Precondition: стол T-3 занят .
Шаги:
1. Менеджер создаёт бронь для T-3  (после буфера).
2. Менеджер создаёт бронь для T-3(внутри буфера).
ОР: 1 — успешно; 2 — отклонено с указанием на конфликт/буфер.

### TC-MGR-003 | Матрица доступа | BP-08 | integration | P1
Шаги:
1. От роли гость попробовать опубликовать схему.
2. От роли менеджер попробовать изменить роль пользователя.
3. От роли админ изменить роль пользователя.
ОР: 1 и 2 — 403; 3 — успешно.

## 6. Тест-кейсы: Визуальные статусы (цвета столов на canvas / FloorPlanSVG) (VIS)

Цвета и стили взяты из project/client/src/components/FloorPlanSVG.tsx:
- available — обводка #3A2E24, без overlay, без хэтча.
- optimal — обводка #2E5A45 (зелёный), без overlay, без хэтча.
- occupied — обводка #8C3B35, overlay #8C3B35 opacity 0.28, хэтч url(#plan-hatch) (красный, заштрихованный).
- not_suitable — обводка #8C8069, штриховая линия (dashed), dim 0.45 (серый).
- В режиме manager: occupied — обводка #8C3B35, overlay 0.2.

### TC-VIS-001 | Стол свободен, подходит по гостям | BP-09 | unit + component | P0
Precondition: гостей = 2, стол seats = 2, нет броней на слот.
Шаги: открыть схему в режиме booking.
ОР: обводка стола #2E5A45 (optimal), нет хэтча, нет затемнения.

### TC-VIS-002 | Стол свободен, но не подходит по вместимости | BP-09 | unit + component | P0
Precondition: гостей = 6, стол seats = 2, нет броней.
Шаги: открыть схему в режиме booking.
ОР: обводка #3A2E24 (available), нет хэтча, стол не помечен как оптимальный.

### TC-VIS-003 | Стол занят подтверждённой бронью на слот | BP-01, BP-09 | unit + component | P0
Precondition: на столе confirmed бронь на выбранный слот с учётом буфера.
Шаги: открыть схему в режиме booking.

Шаги: открыть схему в режиме booking.

### TC-VIS-005 | Визуализация soft-lock стола | BP-04 | component | P1
Precondition: мягкая блокировка стола активна (таймер 300 с).
Шаги: открыть карточку стола / схему.

### TC-VIS-006 | Инструменты конструктора на столе | — | component | P1
Precondition: режим constructor, стол выбран.
Шаги: кликнуть на стол в схеме.

## 8. Тест-кейсы: Нефункциональные требования (НФТ, ПЗ №3 Бланк 8)

### TC-NFR-001 | p95 ≤ 1.5 с, 5xx < 0.1 % | — | performance (k6) | P0
ОР: при 100 одновременно активных пользователях API доступности отвечает за p95 ≤ 1.5 с, доля ошибок 5xx < 0.1 %.

### TC-NFR-002 | FPS конструктора ≥ 50 | — | performance | P1
ОР: на схеме до 100 столов редактор удерживает ≥ 50 FPS, отклик UI на перетаскивание ≤ 16 мс.

### TC-NFR-003 | RBAC HTTP 403 | BP-08 | integration | P1
ОР: неавторизованные запросы к операциям конструктора/менеджера возвращают 403.
